paydesk.

Salary management · implemented system architecture

10,000-employee assessment target

One application, two roles, one source of payroll truth. Next.js + React + TypeScript; single app writer and encrypted SQLite on persistent disk. HR manages payroll; employees access their own records.

01 · Payroll correctness

Integer minor units + currency; one tested formula with explicit rounding. Saved monthly snapshots preserve processed history.

Stale-version checks prevent silent overwrite. Code validates every sheet row; owner-bound draft → HR preview/confirmation → transactional commit. Claim approval recalculates the month.

Net = gross − unpaid-leave deduction − other deductions + approved reimbursements. No invented tax/PF/ESI rules.

02 · Security boundaries

Salted scrypt passwords; signed HS256 JWTs, revocable sessions and rotating refresh tokens. Access: 10 min; idle: 30 min; absolute: 8 h.

HttpOnly/SameSite cookies; Secure + HTTPS in production. Server-side role/ownership checks, Origin checks, bounded inputs and ClamAV. Database page encryption; Drive tokens use AES-256-GCM; secrets stay separate.

03 · Performance and request control

Indexed keyset pagination: 25 employees/request. SSR seeds React state + account-scoped JSON memory cache: 15 s TTL / 50 entries; identical in-flight reads share work.

300 ms search debounce, 500 ms filter-submit throttle, pending guards, lifecycle aborts and response sequence checks. Explicit refresh and lifecycle/session clearing bound staleness.

No generic mutation cache; aggregate request counters are diagnostics, not full production monitoring.

04 · AI with restricted authority

Purpose/readability review only after scans; valid uploads proceed with visible unavailable status on AI failure. AI samples sheets; code validates all rows.

Encrypted local passages/vectors; bounded retrieval, explicitly shared policy text and authorized payroll. English OCR for printed documents. Citation/number checks; calculations in code.

No AI payroll writes/approvals or invented deduction reasons. Conversations reset on full navigation.

05 · Deployment, evidence and next scale boundary

Deploy: one app writer, persistent encrypted disk, HTTPS, Google OAuth, ClamAV, same-host Ollama and native OCR binaries. Move the repository adapter to PostgreSQL when multiple application writers are required. SQLite/Drive/AI are not a distributed transaction; durable ingestion, reconciliation, backups/key recovery and notifications need operational follow-up.

Evidence: 316 tests / 51 files; TypeScript and production build passed. Browser role/upload/chat checks, native OCR and synthetic real-model checks have separate execution evidence in docs/CURRENT_TEST_CASES.md. The 10,000-row seed is tested; concurrency/latency capacity is not benchmarked.

Scope: implemented assessment system, not a production certification. Details: ARCHITECTURE.md · REQUIREMENTS.md · SECURITY.md · DOCUMENT_AI.md. Model interpretation, scanned text quality and external service quotas remain review/operational concerns.
